# 取证过程中造成的虚拟机损伤记录

## 时间
2026-09-23 (Termux 宿主时间)

## 现象
虚拟机 (127.0.0.1:6556) 的 `/system` 投影失效：
- `/system/bin/sh`     → No such file or directory
- `/system/bin/toybox` → No such file or directory
- `/system/build.prop` → No such file or directory
- `/system/etc/hosts`  → No such file or directory
但 `/init.rc`、`/vendor/bin/sh` 仍可读 → 只有 `/system` 子树失效

结果：`adb -s 127.0.0.1:6556 shell` 报 `exec '/system/bin/sh' failed`

## 可疑操作序列
1. `mount -t tmpfs tmpfs /mnt/t1`          → ret=0
2. `mount -t proc proc /mnt/t2`            → ret=0
3. `mount -t tmpfs -o ro tmpfs /mnt/ro`    → ret=0
4. **`mount --bind /system /mnt/t2`**      → ret=0   ← 高度可疑
   （此时 /mnt/t2 已经叠加了 proc）

## 虚拟机当前挂载表中的残留（重复叠加，说明实现有 bug）
```
tmpfs /mnt/t2 tmpfs rw,seclabel
proc  /mnt/t2 proc  rw,seclabel
/system /mnt/t2     rw,seclabel      ← bind
proc  /mnt/t2 proc  rw,seclabel      ← 第二次测试叠加
/system /mnt/t2     rw,seclabel      ← bind 第二次叠加
tmpfs /mnt/t1 tmpfs rw,seclabel
tmpfs /mnt/ro tmpfs ro,seclabel
tmpfs /mnt/ro tmpfs ro,seclabel      ← 重复
```

## 推断
虚拟机的用户态挂载实现，对「向已挂载目标做 bind mount」处理有缺陷，
可能把源 /system 的 VFS 路径映射覆盖/解绑，导致 /system 子树整体不可解析。
内存态破坏，重启实例应可恢复。

## 恢复方案
在宿主侧强制重启实例：
  adb -s 127.0.0.1:5555 shell am force-stop com.vphonegaga.titan
然后在 App 里重新打开虚拟机实例。
